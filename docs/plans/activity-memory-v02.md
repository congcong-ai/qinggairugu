# 倾盖如故 v0.2 增量实施计划

## 当前执行基准

2026-10-22，用户审核原增量计划后进一步明确：**录音和图片全部只保存在用户手机本地，不上云**。本修订优先于原需求文件的 OSS 照片条款。不配置对象存储，不提供服务端照片上传接口；小程序不提供录音、选图、拍照或图片上传，相关入口引导下载 Android App。App 支持相册导入和拍照，并保存独立的私有持久副本；删除相册原图后仍可读取。保存无需联网，不支持跨设备读取，卸载 App 或清除应用数据后本机记录丢失。AI 整理的联网与临时上传另行说明。

云端复用活动、微信身份、参与资料和共享回顾；新增本人文字心得及显式授权的私有 AI 文本副本。录音、图片、Embedding、Key 不进入产品服务器。使用百炼整理时音频由手机直达用户配置的百炼临时服务；不使用 AI 则无需发送。

## 已有能力及复用

基线 4e12354。已有 Expo 58 / React Native 0.88、Taro 4.3、Hono、PostgreSQL / Drizzle、SQLite 正式迁移、BYOK 百炼、Speaker、语义搜索、微信加入和共享回顾。复用全部现有管线，不重建项目。包名、签名、AppID、pengtou.db、SecureStore 键及历史 ID 保留。用户 CODEX_PLAN_PROMPT.md、UPGRADE_REQUIREMENTS.md 不覆盖。

基线 55 项常规测试和 3 项 PostgreSQL 集成测试、lint、9 包 typecheck/build 通过。Android JS 导出不等于 APK 验收；历史真机证据见 DEVELOPMENT.md，本次无 ADB 设备需重验。

## 模型与权限

- 复用 sessions、participants、users、installations、recaps。不新增平行 Activity 主表或全局组织者角色。
- personal_entries 为私人文字记录，可不引用共享活动；关联只建立引用，不合并心得、不改录音 ID。
- 本地 personal_photos 保存持久文件引用，不存在云端照片表或路由。
- 一个微信可绑定多台设备；一台设备只有一个有效绑定。设备申请 5 分钟挑战→微信认领→原 App 核对身份确认。只存令牌摘要，限制猜码、重放和并发确认。
- 匿名设备场次保留设备所有权；绑定账号仅在有效绑定期间获得派生管理权。微信创建场次归微信用户，绑定设备代理。
- 私人文字仅本人；私有 AI 还须来源绑定有效。成员不能替创建者发布回顾。普通后台无私人正文读取接口。
- 私有同步和共享发布独立 API/按钮；全文默认不选。重整理仅提示有新版本，不自动扩大同步范围。取消/解绑删除副本，不动原机录音、照片和 Key。

## 接口及迁移

保留旧 /sessions、/join、/participants、/recap 形态，新增 /me/activities、/me/entries、/bindings、/me/private-ai。严格 DTO 拒绝录音、图片、Key、向量及未知字段；私有文本同步单独受限 4 MiB，其它请求维持 128 KiB。版本号防并发覆盖；删除 AI 保留空内容撤销版本防旧任务复活。

云端追加 0002 身份/活动/绑定、0003 私人文字、0004 私有 AI、0005 回顾修订/撤回/归档。0001 checksum 不改。有序清单、事务、advisory lock 保留旧 ID 和数据。SQLite 保留 1/2，追加 3 本地心得/照片/缓存/任务、4 导入来源/元数据/指纹、5 同步状态/来源版本。不自动上传或重算历史内容。

所有云端调用显式解析本地 ID→云端 ID；客户端 UUID 保证离线重试幂等。同场记录分组但分别保留。私人删除不影响共享活动及他人记录；共享活动归档；账户删除撤销身份及本人私人文字、参与资料，归档本人创建场次并撤回回顾。

代码回滚保留新增结构，不破坏性 down；SQLite 升级后用兼容修复包，不能直接降装旧 APK。部署前备份并在旧数据副本演练，不自动恢复数据库覆盖新数据。

## 阶段

| 阶段 | 实现模块                                  | 验收                                             |
| ---- | ----------------------------------------- | ------------------------------------------------ |
| P0   | 计划/配置缺口/基线                        | 保留用户原文件，记录实际结果                     |
| P1   | database/contracts/API/双端绑定           | 旧链路、迁移、过期/重放/多设备/解绑              |
| P2   | 私人 entry、统一时间线、心得/文字认识的人 | 小程序无主办方独立使用；混合关系无切换           |
| P3   | App 相册导入/拍照/独立副本/删除           | 退出重进可见，网络无照片上传；小程序引导下载 App |
| P4   | 微信发起/官方码/分享；App 加入和参加活动  | 双端创建/加入、旧码兼容                          |
| P5   | 系统音频导入/持久化/复用 AI               | m4a/mp3/wav 真样本及损坏/取消/空间/重启          |
| P6   | 私有 AI 文本主动同步/查看/撤销            | 本人可读，同场他人和旧绑定拒绝                   |
| P7   | 共享回顾修订/撤回、候选关联/解除          | 成员不得发布，私人信息不泄露                     |
| P8   | 设备/微信/兼容/隐私/官网/发布             | 真实证据与待验收边界分别记录                     |

音频单次一个文件，m4a/mp3/wav，上限 200 MiB/2 小时，实际取模型限制更小值。解码和时长校验，复制到持久目录后完成，失败可恢复；指纹只提示重复，不合并。不新增转码依赖。App 本地照片每记录 9 张，压缩到 2 MiB/1920 像素，不上传。

## 测试、风险与发布

重点风险：身份误绑定、ID 错场、私有误公开、可见性旧缓存、解绑/删除与重试竞争、多端覆盖、导入影响录音、发布包漏迁移。通过显式确认、集中权限、ID 映射、版本和绑定锁、本地文件检查及录音隔离处理。

迁移覆盖空库/v1/v2、重复/失败/checksum/旧客户端，核对历史 ID/关系；绑定覆盖过期/猜码/并发/重放/错误设备/多设备/解绑；同步覆盖字段注入/授权缩小/版本/撤销；媒体验证没有产品上传接口且 DTO 拒绝媒体。录音至少 2 小时并验音频可解码；真实两设备和微信工具、APK 覆盖安装保留。

七条验收按用户新边界执行：1 小程序独立文字记录（照片改为 App 本地）；2 微信 A 发起 B 加入；3 原录音→码→加入→Speaker→BYOK→发布；4 参与者导入→绑定→本人同步→撤销；5 同人多关系统一时间线；6 候选明确关联且私人不暴露；7 匿名/非成员/跨场/同场他人/旧绑定越权。

每阶段相关测试、lint/typecheck/build；共享契约变更完整回归。配置不足继续开发，不把 Mock/编译作为真实设备成功。待补仅设备、微信当前有效性、正式签名核验；不再需要 OSS。部署沿用现有入口、健康检查及回滚，当前不自动发布。新 Mobile/共享代码需正式 APK 重建和清单检查。
